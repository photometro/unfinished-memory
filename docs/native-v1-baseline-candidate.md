# 原生 V1 本地产品基线评审稿（第10条 R3）

状态：用户已认可本地产品基线作为后续本地原生实施输入（2026-10-07）。本文只签收页面／状态／数据基线；不表示当前 Android 已实现新版 UI，也不代表原型整体已视觉签收，更不授权开始第11条。

## 1. 本稿要解决什么

第10条把已验收的 Room 业务状态底座、当前 Web 原型和 V3 已确认边界，整理成后续本地原生版可共同引用的页面／状态／数据基线。实施顺序仍是：先完成本地可用版本，服务端和数据库接口预留但不作为启动、书写、封存、过去或遇见的前置条件；后端贯通及跨设备同步／恢复在后续阶段单独验收。

学校最终要求仍是前后端与数据库贯通、至少六个真实前端功能页面。本地阶段是分阶段交付，不替代最终要求；六页按实际任务页面验收，不把动画、弹窗或辅助步骤拆页凑数。

按 #17 的核心任务口径，六个可验收页面是：首页、书写、过去、遇见／回忆、原文／回应、设置。留线索、补充背景、怎样回来等辅助页可以独立导航，但不需要靠它们或封存动画凑足六页。

本稿的结论口径：

- “已确认”表示可作为本地实施输入，不需要重新询问用户。
- “工程预检”表示由后续对应任务验证兼容、格式和失败边界，不是假装已经完成。
- “待决定”只保留确实尚未收口的事项；不能把原型预览状态、旧候选文本或实施者建议写成用户选择。
- 本地基线获签不等于完整 UI 美学签收、算法参数冻结、后端生产协议验收或第11条实施批准。

## 2. 已确认的本地产品基线

### 2.1 技术与阶段边界

- 正式客户端采用 Kotlin／Jetpack Compose 与 Room；后端采用 Java 21／Spring Boot／PostgreSQL，作为后续前后端阶段，不要求本地版依赖服务器。
- 已选择 `Kyant0/AndroidLiquidGlass` 作为液态玻璃实现方向；最低支持 Android 13／API 33，以满足所需透镜效果与嵌入可变字体条件。库版本、API 调用、许可证、系统降级和构建兼容性仍须工程预检。
- 本地库是 V1 本地阶段的数据事实来源；沿用稳定本地 ID、scope 与版本。远端身份不能替代本地业务身份。无 AI、无网络、业务后端关闭时，核心本地流程仍须可用。
- 不做 WebView 外壳；不新增可见登录或管理后台；不做本地导出备份。接口预留不应伪装成已连接或已同步。
- 第10条 R1 的临时服务端／PostgreSQL 往返是隔离技术验证，不是本地运行依赖，也不是完整生产同步／恢复已验收的证据。

### 2.2 首页与环境

- 首页构图已选 **A「横向潮滩」**，以当前原型为视觉和布局参照；A/B/C 不再是待选项。
- 常态首页保留「留下一段」「过去」和设置入口，不加底部 Tab、洋流导航或永久「主动遇见」按钮。
- 只有存在持久化待处理遇见事件时，首页才显示该事件的回忆出口；没有事件时保持普通首页。这个条件式入口已经确认，不等同于用户主动创建新事件的正式路径。
- 环境采用三态：日光 06:00–14:00、斜阳 14:00–18:00、夜色 18:00–06:00，按设备当地时间切换；手动深色模式优先显示夜色，关闭后回到当地时间状态。
- 首页潮位／涨退潮视觉目前暂停，固定呈现选定的潮滩画面；不得把历史潮位渲染器或工作台参数重新启用为首页效果。开屏使用配套海面素材与退潮入场，正常完成、跳过、减少动画都到同一时刻对应的首页环境。
- 图片是统一潮滩主题的生成式写实插画，不是实测航拍、DEM、潮位表或科学水动力模拟。首页潮汐效果暂不进入本地基线实现。
- 三态图片、配套开屏图、裁切和光影已有原型记录，但 UI-CHECKLIST 仍保留用户视觉签收项；记录资产来源不等于替用户完成视觉验收。不得因基线签收擅自改图或宣称全部视觉通过。

### 2.3 留下操作线

默认交互以 Study18 为准：一项主任务一个清晰页面，不放顶部流程条，不叠加浅色“书写底板”，不把内容页面做成浮层卡片。可选辅助信息各自进入完整页面，返回原步骤时保留同一份草稿。

| 步骤／页面 | 用户任务与状态 | 提交、返回与保护规则 |
|---|---|---|
| 书写 | 输入要留下的文字、添加静态图片；空稿、文字、纯照片、图文、草稿恢复均须有状态 | 继续／暂存不等于封存；返回、旋转、重建和失败恢复不得静默丢稿 |
| 封存前 | 原文／照片为主体；线索建议默认可见但不默认采用。可以采用、编辑、移除、自写或跳过；可进入补充背景与出现方式 | 只有明确采用／编辑确认／自写的线索写入记忆；没有 Cue 仍可封存，也仍有资格进入算法候选池 |
| 补充背景（可选） | 日期、地点、人物、来源等用户填写的元信息均可空 | 保存到同一草稿；返回进入它的步骤，字段不丢失；不得自动生成正文标题 |
| 怎样回来（可选） | 偶然遇见、指定日期、静静保存；选择固定日期时再显示日期输入 | 固定日期缺失或无效时就地提示；更改方式不擅自删除仍有效的历史信息 |
| 确认封存 | 只读预览原文、已采用线索、元信息和出现方式；唯一明确的最终提交入口 | 提交期间防重复；失败停留并保留草稿；只有本地事务成功后才进入封存仪式 |
| 封存完成 | 原确认页连续折成纸船，进入蓝色流场；纸船离开后洋流持续可见 | 纸船折叠／漂走是已保护的原型设计，本地基线不重设计或替换；减少动画使用静态完成态 |

原型 Cue 是有限的本地原文摘词演示，不是 AI、V3 评分或通用语义提取。正式版可在用户配置 AI 且授权的范围内给出可编辑建议；未配置 AI 时核心流程仍完整，未采纳的建议不能写入 CueBank。AI 不是浮现资格条件，也不得越过 V3 的输入白名单。

### 2.4 遇见与回忆

- 首页只消费已持久化的 active／pending 事件；无事件时不临时抽取或创建记录，也不显示空的遇见选项。
- 事件存在时可进入回忆、请求线索、直接查看或暂缓；没有可用 Cue 时不显示无效的“再给一点”操作。
- `STOP_RECALL` 与 `DIRECT_REVEAL` 是持久化业务状态；STOP 后不再给 Cue 或让 AI 追问。正文、照片只有成功进入可见状态才记原文曝光并更新冷却；点击、预取或加载开始不算曝光。
- 不因“没想起来”强迫作答。直接看、暂缓和离开都应是可用出口。
- **正式主动创建新遇见的入口／触发路径仍待 #14 单独确定。** 不得据此增设首页常驻按钮，也不得把设计工作台的“演示记忆上岸”当成产品入口。

V3 的模型结构与业务边界已确定，算法参数仍需标定。资格检查、发生决策、候选加权随机选择、回忆交互彼此分层；Cue 是交互资源而非候选资格。Weibull 参数、候选权重函数、情境系数和 Cue 评分参数仍由 #14 参数规格／合成模拟／体验复核完成；本稿不填入猜测数值，不批准生产评分。

### 2.5 过去与设置

- 过去首阶段只搜索日期、用户明确标题、地点和人物等元信息；不搜正文全文、图片 OCR／正文片段，也不加入来源或策略筛选。
- 列表不从正文前 N 字自动造标题或摘要，不在列表直接泄露正文／原照片。无明确标题时用日期与已填写元信息组合标识。
- 这要求本地数据结构可以保存已确认的元信息；当前 Room 实体尚无地点／人物／来源字段，需由后续数据阶段通过可迁移 schema 补齐，不回填猜测值，也不把正文复制进索引。
- 设置承载本地显示／回忆偏好、用户自定义 AI 提供方与隐私入口；没有 AI 配置、断网或后端关闭不影响查看与保存。
- 通知只在用户开启提醒时请求授权；拒绝或撤回不阻止本地操作、固定日期记录留存或前台到期检查；通知内容不得泄露原文和照片。

### 2.6 本地数据与媒体

- 本地记录、草稿、Cue 授权／采用、出现策略、遇见会话、曝光与冷却状态均由本地持久化层承载；按 #9 冻结的事务、每日决策与状态迁移规则执行，UI 不在 ViewModel 内臆造业务事实。
- 每段最多 20 张静态图片；私有原图与缩略图分开保留，默认不因添加图片而允许 AI 读取或发送图片。附件／来源授权必须独立。
- 用户不要求第一版提供本地导出备份；系统数据恢复、卸载、换机后的跨设备恢复不在本地里程碑承诺内。
- 支持格式、持久 URI 获取、文件／像素上限、解码内存保护、缩略图尺寸、加密封装与错误恢复属于 #12 的工程规格和验证，不在本稿里编造尚未批准的技术数值。

## 3. 视觉与弹性布局基线

功能页使用各自整页底色，不另叠“浅色书写底板”：

| 页面组 | 日间 | 夜间 |
|---|---|---|
| 留下、线索、出现方式、辅助页、确认、阅读／回忆／回应 | `#F2EADF` | `#302D29` |
| 过去／搜索 | `#E6EDF0` | `#263842` |
| 设置 | `#E8ECE6` | `#2D3732` |
| 封存洋流 | `#3C6074` | `#274758` |

功能页全页同底色；首页继续使用三态潮滩与玻璃控件。中文可变字体需嵌入应用资源，不能依赖设备字体回退；液态玻璃以选定库实现，正文层级仍靠字号、字重、间距和对齐，不把所有信息平铺成同权重块。

采用弹性内容轴与自然滚动，不按魅族21写位置常量。基线测试窗口为 320×568、360×640、390×844、600×960 dp，字号比例 1.0／1.3；覆盖短屏、宽屏、软键盘、安全区、系统返回和减少动画。此矩阵用于发现布局问题，不表示其他尺寸不支持。

推荐性能验收目标已接受但尚未测量：60Hz 场景下 p95 帧时长 ≤16.7ms，>33.3ms 帧占比 <1%；至少测冷启动至可操作、主要转场、折船／环境切换长帧、图片解码峰值内存与后台恢复。报告需记录设备和 API；目标值不能写成测试结果。

| 场景 | 必须检查的结果 |

| Cue | 默认可见但未采用；采用／编辑／自写／移除／跳过分别正确；无线索仍可封存和后续进入候选池 |
| 出现方式与背景 | 可选页返回不丢输入；静存不保留无效的随机遇见状态；固定日期校验和到期队列遵循业务协议 |

| 设置／环境 | 日夜优先级、当地时间边界、无 AI／断网／业务后端关闭、通知拒绝／撤回、减少动画均不破坏本地流程 |
| 兼容与布局 | API33 及以上；已嵌入字体和所选玻璃库实际工作；多窗口、字号、键盘、安全区可操作，不依赖单机坐标 |

## 6. 保留为后续决定／工程预检的事项

1. **用户复核本稿**：确认这份本地页面／状态／数据输入可以供后续原生实施引用。此复核不等于原型美学或 Android 视觉签收。
2. **第11条另行批准后再实施**：先落实已确认设计系统、字体、玻璃库和首页／开屏结构；不得在本轮把旧三卡视为新版验收样式。
3. **#12 工程预检**：确定并验证 Android 资源打包、图片格式／大小／像素／解码限制、原图与缩略图、私有存储与加密；这些是执行规格，不应再次把“最多20张、私有原图”当待选项。
4. **#14 保留的产品／算法待决**：主动创建新遇见的正式路径；V3 发生与选择参数的标定和体验验证。首页当前的条件式事件入口不因此重新讨论。
5. **#15 及后端阶段**：正式鉴权、同步、冲突／墓碑呈现、恢复凭据、跨设备恢复及旧密文迁移产品化。#10 的隔离往返不能替代这阶段验收。
6. **本地版最终验收**：至少六个真实任务页面、三条操作线、本地持久化、真实设备／窗口／字号／键盘／性能证据和独立复核；本地通过不等于满足学校最终前后端数据库要求。
