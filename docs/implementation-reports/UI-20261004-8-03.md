## 实施过程中发现的问题

### P-01 大浪来自图片本身

- 现象与发现阶段：旧底部有宽大浪脊，降低shader位移仍存在。
- 根因：sea-noon位图已经画入明显起伏；仅换新淹水层也会残留母图原水面。
- 影响：不符合浅滩宁静尺度，首页和开屏不协调。
- 是否在计划内：是，用户明确要求降低波浪。
- 处理与验证：新平静水面另存，同时覆盖既有水域的主要比例，细节.52、折射.00065；四时×三潮位实际检查，不删除旧图。

### P-02 夜间高潮主沟辨识不足

- 现象与发现阶段：较暗夜间／高潮候选把主沟也压得不清楚。
- 根因：淹水覆盖与夜间暗调叠加，缺少水下深浅。
- 影响：地貌识别点弱。
- 是否在计划内：是，R2要求高潮保留主沟或入海口。
- 处理与验证：夜间亮度.44、适度环境补光，加.10通道深浅；全海入场时深浅痕迹消退，避免海面出现幽灵潮沟。最终夜间低中高图均已查看，仍待用户观感判断。

### P-03 浏览器证据与DOM布局不一致

- 现象与发现阶段：按DOM rect制作CSS裁切，截图对照只露出App一条边。
- 根因：截图后端1082px布局与DOM检查视口不同；具体浏览器实现原因未确认。
- 影响：初始对照裁切无效，不能当作UI证据。
- 是否在计划内：工具诊断，非产品改造。
- 处理与验证：原始完整20图保留，用截图观察到的范围制作展示裁切；页内明确不是尺寸验收。实际尺寸依据独立DOM容器记录；临时浏览器视口已复原。

## 踩坑与防复发

- 触发条件：用户指出大浪、时段暗淡、潮位始终一样。
- 错误做法：只减动画强度、只重做早午、只增加入场退潮，就称问题解决。
- 根因及证据：纹理里有浪脊，统一全图矩阵缺少不同光感；原潮位虽存在但显露范围不充分。
- 正确做法：检查素材／地貌／光照／潮位各自来源；全部四时交叉多潮位；既有水面与新增淹没一起处理，原地貌不随调光重绘。
- 下次预检：区分候选地貌认可与光照认可；对照实际最终渲染，不把SVG缩略图或DOM截图裁切当成最终视觉／尺寸证明。
- 可自动化：共享材质纯测试、19字段有限性和差异、连续潮位、同源入口、保护文件哈希；不能替代动态观感及CPU/GPU实测。
- 建议归档位置：本地报告／资产文档／专项证据。本轮不升级为永久生产规则、不上传知识库。
