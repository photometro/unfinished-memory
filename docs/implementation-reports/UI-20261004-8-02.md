## 实施过程中发现的问题

### P-01

- 现象与发现阶段：预检发现双环境实例、开屏强制退到0、首页level0；候选又强制中午，调光切换会退出母图。
- 根因：入场、首页、候选与时段各自拥有不一致状态。
- 影响：末帧跳图、用户素材选择丢失，额外纹理占用。
- 是否在计划内：是。
- 处理与验证：一持久环境+共享tide/target MotionValue；开屏只驱动progress；光照独立解析。浏览器一实例，入场中改到morning/mid后skip为shore/.3000。

### P-02

- 现象与发现阶段：独立审查指出静态节流的下一帧分支并未等待100ms；同时逐像素创建数组。
- 根因：rAF不是间隔门禁，回调没有更新统一时间戳。
- 影响：CPU降级设备可能高频重算。
- 是否在计划内：是。
- 处理与验证：single trailing timeout、地形height/channel预缓存、标量像素合成；隐藏／退出清理。静态退潮采样counter11→37、终态.3000；源码复核Pass。不是CPU帧时认证。

### P-03

- 现象与发现阶段：独立审查发现15s轮询可能迟于真实边界，skip按钮24px未接safe-area。
- 根因：没有对齐边界计时；安全区规则只覆盖首页／任务页。
- 影响：跨时段短暂滞后及开屏按钮进入顶部保留区域。
- 是否在计划内：是。
- 处理与验证：下一当地边界timer+轮询／focus／pageshow／visibility重算，skip max-safe-top。32个环境测试及实际05:59:58→早上、模拟top44px检查。

### P-04

- 现象与发现阶段：浏览器模拟datetime-local填入值但onChange-only没有更新React，后续渲染复位。
- 根因：该日期控件／UI桥接事件兼容，不能把DOM值当成已应用的预览状态。
- 影响：设计验证时钟不可靠，不是算法或系统时钟问题。
- 是否在计划内：是。
- 处理与验证：兼容onInput，推进的测试时钟独立于真实时间及艺术潮位；重新观察night→morning和书写保持。普通恢复自动与深色关闭清除测试覆盖，不改设备时间。
