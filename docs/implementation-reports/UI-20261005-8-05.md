## 实施过程中发现的问题

### P-01 海面失败会连带遮挡成功岸图

- 现象与发现阶段：独立 post-review 指出新冻结分支沿用 Promise.all，把两张素材的成功绑定；海面失败也让可用岸图无法进入 shown，替换失败时错误层还会遮住旧图。
- 根因：继承旧渲染器的失败耦合，非本轮独有问题。
- 影响：首页背景降级不必要地丢失，入场准备可能被错误阻断。
- 是否在计划内：属于原型资产降级保护，技术修补不改变产品决定。
- 处理与验证：岸图与海面独立加载；岸图完成/失败独立释放入场，海面失败不触发岸图错误，新岸图失败保留上一张，不用满屏错误遮住它。onload后decode，取消回调防过期；海面失败、岸图失败且海面未决、取消加载三项测试通过，独立复核关闭P-01。
- 未覆盖：浏览器真实网络失败/慢解码/海面延迟到达可能造成的视觉突现，仍待专项，不能用可控单测冒充实际注入。

## 踩坑与防复发

- 触发条件：审核图片已经带光影，接入后又按旧shader重新调色或覆盖水域。
- 错误做法：只改图片路径而保留二次处理，或藏潮位按钮但后台仍推进水位。
- 根因及证据：渲染器的旧处理链与本轮“原图固定”目标不同；用户连续反馈亮度和自然逻辑问题。
- 正确做法：冻结分支明确不挂载旧处理链，审核像素直接显示，开屏海面与首页岸图各自处理；规则仅有一个有效时段来源。
- 下次预检：检查实际DOM图片/filter、noon/tide兼容、暂停timer、同态入场终点、异步失效及草稿保护，不能只靠测试数量推断好看。
- 可自动化：时间边界、取消回调、资产独立失败、比例映射与保护哈希；美学和真实网络时序不能完全替代。
- 建议归档位置：本地报告与以后批准的专项契约，不更新全局记忆或外部知识库。
