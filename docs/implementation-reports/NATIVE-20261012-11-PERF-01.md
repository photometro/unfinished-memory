### 保留的优化与实测依据

1. 海图此前由窗口与Compose分别加载；现在在资源ID一致时直接借用窗口Bitmap，避免这一次额外解码。跨时段则独立加载并拥有新资源，不能回收旧窗口持有图像。夜间启动仍需要当前岸图与白天揭示参考，不误删这两次必要加载。
2. 字体TypeFace及固定文本准备在IO；首页子集保留五档字重，因为两台设备存在fontWeightAdjustment，不能只保留400／500。749个所需字形在五字重下轮廓、advance、行高和variation轴均与原字体一致；3项Compose像素对照通过。字体准备P50：全量预热探索组约162ms／119ms，最终约90ms／47ms（18s／21）；这是资源准备改善，不是整个初始化通过。
3. 首页渐显外层消除额外全屏alpha离屏缓冲；有RenderEffect的局部玻璃控件保留自己的处理。ModulateAlpha对重叠内容的混合可能不同，所以同时检查终态与窗口恢复，不直接批量替换所有graphicsLayer。[Compose图形官方文档](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers)
4. 不增加停留、遮罩、白色覆盖或手动入场按钮来掩盖慢帧。原图片首帧方案、小窗声明／配置处理、岸边取景与底部锚点全部保留。

### 性能指标定义及限制

- 每轮：force-stop → HOME → 500ms →系统Perfetto → `am start -W` →6秒轨迹。所有最终launch日志为COLD；普通Debug、不运行额外ART speed命令。没有清ShaderCache，属于自然GPU缓存状态，首轮是本次安装后采样首轮，不等于首次安装／GPU完全冷缓存。
- 逐帧CPU口径为同帧UI doFrame开始至RenderThread drawFrame结束的时间跨度，不是纯CPU正在运行的累计时间；overrun使用实际／RenderThread结束较晚者减expected deadline。采用AndroidX查询公式重算，**未直接使用包含app_vsync_delay的Perfetto cpu_time**。[AndroidX FrameTimingQuery源码](https://android.googlesource.com/platform/frameworks/support/+/dd97834aa54671ee1f56d65fa46668b4ffeb57e8/benchmark/benchmark-macro/src/main/java/androidx/benchmark/macro/perfetto/FrameTimingQuery.kt)
- 本轮没有运行官方Macrobenchmark Runner；SQL连接和驱动重同步可能产生微小差别，属于同定义近似，不冒称正式Macrobenchmark输出。旧轨迹手工重算约96.79／116.23ms，与旧JSON约96.72／116.17ms接近，可用于核对定义。
- 初始化按动画标记之前**全部有效帧**的逐轮最大值统计，不只取第一／第二帧，不删除首轮或慢轮。动画严格按Opening.Animation标记统计，包含首页渐显交接。P95／P99采用nearest-rank。
- baseline只有每机5轮且没有动画标记；它的SceneReady统计从揭示场完成＋350ms估计，不能与最终精确动画窗口当作严格同范围A/B。各5轮探索组为顺序诊断，不证明单一改动因果或统计显著性。
- 个别驱动轨迹报告negative timestamp dropped，解析日志保留；只统计具备有效UI／RenderThread／expected／actual关联的帧，不把丢失／不完整帧当作正常帧。
- TTID使用am start的TotalTime，不等于首页真正可交互。没有完整的精确交互埋点，不能把动画结束或首张截图当作全部TTI验收。

## 实施过程中发现的问题

- “冷启动性能尖峰”至少包含首次UI创建／排版、资源准备、GPU首次绘制和动画交接；不能合成一个平均值。
- 原始普通Debug初始化CPU峰本来就约200–250ms。保留Debug的类校验／解释执行开销显著，原隔离release-like结果与普通Debug不能直接同表宣称退化或达标。
- 只有资源准备及动画改善；18s TTID和首排版没有证明改善，存在本轮性能未通过的真实剩余项。
- 试验中的开屏字体路径改变并不符合“保留已签收视觉”，最终恢复原解析；没有要求用户为该失败试验重新签收。
- Bitmap所有权必须和已加载结果绑定，否则切换时段可能错误回收借用资源；此问题在上机前审查修正并补测试。

## 计划偏差

- 不再使用隔离目标和手机Runner，按最新授权改系统Perfetto＋普通同包Debug；模拟器仍使用既有测试Runner验证UI。
- 新增首页固定UI字体子集、生成工具和覆盖门禁；原因是全量字体准备仍昂贵，保留字形和原完整字体。未删字符支持或换字体。
- 本轮未改变正式R8／Baseline Profile部署或普通包debuggable配置。初始化目标未满足，不能把“构建成功／已装机”当作“性能完成”。
- 原基线仅每机5轮且缺精确动画标记；最终每机30轮，明确对照限制，不补造旧标记或删样本。

## 踩坑与防复发

- 冷启动编号不等于GPU首次冷缓存；需要分别报告，不偷偷清用户App数据来制造或掩盖结果。
- 最终采样结束后再枚举所有trace；本轮分析曾提前看到29条，已在全部30条完成后重新计算，不用不完整快照签收。
- 区分原始baseline、中间final、最终final-preserved，所有指标绑APK哈希；不能误把旧专用宏基准包当通用App。
- P95取逐轮初始化最大值；动画需同时看总体和最差单轮，不能只报均值或删首轮。
- 资源优化必须保留退出／时段切换／小窗尺寸变化的所有权与布局语义。字体子集不用于任意正文，增加文案须过构建覆盖门禁。
- 旧合同字段格式问题和产品依赖未满足是两件事。记录自动校验限制、人工核对证据和未完成性能项，不将它们混为“待用户决定”。
