## 实施过程中发现的问题

### P-01 粗中心线造水，完整首页出现蓝色管道

- 发现阶段：首次完整 UI 自检；纯测试通过不等于自然形态和构图可用。
- 根因：按人工沟中心线直接降低高程，形成过度均匀的粗带，且淹水配色取代了母图水色。
- 影响：潮汐树枝杈被抹粗、显得卡通，违背保留母图要求。
- 计划内：地貌／材质修正范围内。
- 处理：中心线仅作源图分类包络，涨水距离以照片实际水岸为基础，原水域不被换色；新浅水保留底色纹理，幅度降低。完整首页再核对12状态。

### P-02 正常开屏与跳过开屏湿边终态不一致

- 发现阶段：独立 post-review。
- 根因：跨 `.57→.52` 判断只适用于大步跳过，正常连续退潮不会同时跨越两个条件。
- 影响：同目标水位下正常开屏有多余大片湿滩。
- 处理：显式 opening 标志统一初始化湿润历史；纯 wetHistory 正常／跳过／减少终态测试，浏览器四时正常＋跳过＋中途减少均 `.3000/.3000`。

### P-03 静态／减少动画下固定潮位湿边不再干燥

- 根因：原 wetHistory 仅随正常渲染帧推进。
- 处理：按墙钟时间计算干燥，静态／减少使用有限0.5Hz任务，隐藏／非活动页／卸载停止；恢复时重新计算。独立复查无阻断，纯测试低频与高频一致。

### P-04 图集首轮准备约876ms，切后端可能重复计算

- 发现阶段：浏览器诊断／独立性能样本。
- 处理：仅缓存一个 packed atlas，释放临时 levels；后端切换准备观测0–0.1ms。CPU／GL 数据 atlas 统一 NEAREST 采样。
- 遗留：首次主线程长任务仍存在；这些数字不是帧率或真机基准，不自动宣称性能通过。

## 踩坑与防复发

- 触发条件：用少量照片做艺术潮位，却按理想中心线或屏幕纵向猜高程。
- 错误做法：纯测试通过就交付；全图水色替换；把日间明亮处理成白罩。
- 正确做法：母图坐标固定，原水色保留，照片不规则岸线＋分区约束＋连通门槛，四时×三潮位放回完整 UI 检查。
- 下次预检：检验初始湿润终态、帧率无关干燥、纹理过滤方式、缓存预算及开屏／首页材质边界；确认真实潮位和艺术模拟不是同一概念。
- 可自动化：地貌连通门槛、保护哈希、wetHistory终态、明确DOM settled状态；美学不能由计数替代。
- 建议归档位置：项目报告／后续性能任务。未更新全局记忆或外部知识库。
