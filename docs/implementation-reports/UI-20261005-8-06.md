## 实施过程中发现的问题

### P-01 后加载CSS再次盖住照片

- 现象与发现阶段：此前宣称首页无全幅遮蔽，但实际浏览器`home-interface::before`仍有顶端alpha.55渐变；C浮现还有额外规则。
- 根因：只看styles.css早期none，漏掉后加载journey.css与变体分支的级联覆盖。
- 影响：顶部灰白、通透度降低；单纯换图无效。
- 是否在计划内：用户明确要求移除遮蔽；D-01补全实际命中规则。
- 处理与验证：只删实际首页渐变；A/B/C×安静/浮现×日/夜12组computedStyle均none/透明，按钮玻璃不改。

### P-02 全幅淡出不表达退潮

- 现象与发现阶段：旧海图只有opacity渐变，mask/clip为none，三个画面无法形成水边退移。
- 根因：把开屏到首页的转换实现为整图交叉淡入淡出。
- 影响：用户要求的一次退潮入场缺失。
- 是否在计划内：恢复开屏退潮；D-02不重启持续首页潮汐。
- 处理与验证：以日光参考照片青色水域采样距离构造艺术化地貌显露场（不是真实DEM、水动力或严格海水连通模拟）；三态共用边界坐标，局部alpha遮罩露出潮滩，海图自身opacity=1。纯测试检验端点/单调/同时透与不透，中帧截图检验实际空间露出，终态卸载。

### P-03 时段文件名与明确选图冲突

- 现象与发现阶段：用户认为当前日光使用了旧中午图；这次附件与历史V5 noon字节相同，但用户明确指定其为日光。
- 根因：历史文件名和用户当前三态语义不是同一约定，不应按文件名推测选择。
- 影响：可能反复接错图或擅自恢复第四态。
- 是否在计划内：用户直接给出唯一编辑基准。
- 处理与验证：原图副本SHA为`25BC53C3E52855E302C11BA2C39F122A7B0E042ACAB1BDFEA07AC2F0C011A2BD`；新图独立命名，不恢复中午态。生成改图不承诺陆地逐像素不变，完整画面仍待用户审核。

### P-04 慢海面可能在退潮途中突然加入

- 现象与发现阶段：预检发现岸图先ready，迟到海图可能在已开始的退潮途中出现；失败还可能拖住入场。
- 根因：就绪与海面准入未分开。
- 影响：突兀、卡住或进入错误素材组合。
- 是否在计划内：加载保护为R5必要技术增量D-03。
- 处理与验证：成功岸图后最多等待1800ms海面+参考图解码；准入后才ready，超时这次不再加入。单测覆盖海失败/岸失败且海不解、迟到、配对ready、取消。未做浏览器真实网络注入，不能宣称已测真实慢网。

### P-05 图片缓存不是全部释放

- 现象与发现阶段：独立复审P2指出模块级解码图缓存最多六张，入场结束后仍可能驻留。
- 根因：为切时段避免重复解码保留Image缓存；只释放遮罩/画布与订阅。
- 影响：六张887×1774 RGBA下限约36MiB，另外还有开屏画布；不是浏览器真实heap/GPU测量。
- 是否在计划内：当前未做图片缓存优化，不擅自扩张范围。
- 处理与验证：README/ASSETS/UI-CHECKLIST/VERIFICATION/清单及报告如实标明。原生/低内存/帧率专项待后续，不能声称已满足真机资源预算。

## 踩坑与防复发

- 触发条件：背景图片替换、后置CSS、开屏到首页、多次时段历史。
- 错误做法：按旧文件名猜图；只检查filter或styles一处；把全幅fade当退潮；把请求viewport或截图尺寸当真实CSS容器。
- 根因及证据：本次SHA、12组级联样式、旧mask/clip为空、hostzoom测量与画面。
- 正确做法：明确用户图→版本化来源→同态配套海图→同一源空间mask→实际完整UI查看→保护区回归；入场结束卸载，不打开首页持续潮位。
- 下次预检：来源SHA/显示图匹配、样式导入/变体全路径、非全幅alpha中间态、晚到素材、减少动画、实际DOM容器和开发HMR状态。
- 可自动化：来源manifest、级联变体浏览器探针、mask端点/单调测试、loader有界准入、保护区差异；图像审美及真实性能不能由纯测试代替。
